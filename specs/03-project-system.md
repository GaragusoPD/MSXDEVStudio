# Spec 03 — Project System

**Phase:** 1 · **Depends on:** 01, 02 · **Suggested model:** Opus 5 (config
generation/import correctness), UI forms Sonnet 5

## Goal

Create, open, and configure MSXgl projects. The IDE owns a portable project file
(`.msxproj`, JSON); from it, it **generates** MSXgl's `project_config.js` before each
build. MSXgl facts this rests on: config files are plain JS executed into globals;
the engine root is implicit (derived from `build.js`'s own path), so **projects can
live anywhere** as long as builds spawn `<msxgl>/engine/script/js/build.js` with
cwd = project dir.

## Project file: `<root>/<name>.msxproj`

```jsonc
{
  "version": 1,
  "name": "mygame",
  "machine": "1",              // "1"|"2"|"2P"|"TR"|"12"|"22P"|"122P"|"2K"|"0"
  "target": "ROM_32K",         // any name from MSXgl setup_target.js (list them all in a shared const)
  "romSize": null,             // KB, mapped-ROM targets only
  "libModules": ["system","bios","vdp","print","input","memory"],
  "build": { "optim": "Speed", "debug": false, "allowUndocumented": false,
             "compileComplexity": "Default", "defines": {} },
  "rom":   { "checkVersion": true, "delayBoot": false, "signature": false,
             "installRamIsr": "RAMISR_NONE", "customIsr": "VBLANK", "bankedCall": false },
  "files": { "rawFiles": [], "diskFiles": [], "diskSize": "720K" },
  "emulator": { "preferred": "openmsx",          // "openmsx" | "webmsx"
                "openmsxMachine": null,           // override; null = C-BIOS default
                "ext": { "scc": false, "msxMusic": false, "msxAudio": false, "opl4": false,
                         "psg2": false, "v9990": false, "ram": false, "pac": false },
                "portA": "", "portB": "", "hz60": false, "fullscreen": false, "mute": false },
  "resources": { "imgRules": [] },               // Spec 07
  "customConfig": false                          // true = IDE stops generating project_config.js
}
```

IDE-only volatile state (open tabs, panel layout) goes in `.msxstudio/state.json`,
gitignored. Single Pinia `projectStore` mirrors the open project; `ProjectService`
in main does I/O (`project:open`, `project:create`, `project:save`, `project:close`,
push `project:changed`).

## Generation of `project_config.js`

Written on every save of `.msxproj` and before every build (Spec 04), with header:
`// GENERATED by MSXStudio from mygame.msxproj — edit settings in the IDE, or set
"customConfig": true to hand-edit this file.` Mapping is 1:1 assignments
(`ProjName`, `Machine`, `Target`, `ROMSize`, `LibModules`, `Optim`, `Debug`,
`AllowUndocumented`, `CompileComplexity`, `CheckVersion`, `ROMDelayBoot`,
`AddROMSignature`, `InstallRAMISR`, `CustomISR`, `BankedCall`, `RawFiles`,
`DiskFiles`, `DiskSize`, `Emul*` flags, `EmulPortA/B`, `Emul60Hz`, …). Omit fields
matching MSXgl defaults to keep the file readable. `defines` map →
command-line `define=` args instead (Spec 04). When `customConfig: true`, never
overwrite; settings UI goes read-only with an "open project_config.js" link.

## New Project wizard

Fields: name (→ folder + `.msxproj` + main C file), location, machine, target
(curated list first: ROM_32K, ROM_48K, ROM_ASCII8, ROM_ASCII16, ROM_KONAMI_SCC,
DOS1, DOS2, BIN — "all targets" expander for the rest), template.

Creates: `main.c` (from `<msxgl>/projects/template/template.c`, or
`template_msx2` variant for machine ≥ 2), `msxgl_config.h` (copied verbatim from the
same template — v1 exposes no UI for it; users edit it as C in Monaco),
`<name>.msxproj`, generated `project_config.js`, `content/` (empty, for generated
asset headers), `.gitignore` (`out/`, `emul/`, `.msxstudio/`), and 2-line
`build.sh`/`build.bat` launchers that call
`node "<msxglPath>/engine/script/js/build.js"` (honoring `MSXGL_PATH` env override)
so the project also builds from a terminal.

"New from example" delegates to Spec 12.

## Opening & import

- Open = pick a folder (or `.msxproj` via file association). If `.msxproj` exists →
  load. If only `project_config.js` exists (pre-existing MSXgl project) → **import**:
  evaluate the config chain in a sandboxed child process (a tiny script that loads
  `setup_global.js`, `projects/default_config.js`, the project's config with `ProjDir`
  faked, then prints the globals as JSON — never `eval` in the main process), map known
  settings into a fresh `.msxproj`, set `customConfig: true` so the original file stays
  authoritative until the user opts into management.
- Multi-project folders (MSXgl `samples/` style `<name>.js` overrides) are out of
  scope for open/import — Spec 12 handles samples specially.

## Project Settings UI

Editor-area tab (registry entry). Form sections mirroring the `.msxproj` schema;
libModules as a checkbox list built from `<msxgl>/engine/src/` scan (top-level
`.c` names + `dir/name` for subdirs); rawFiles/diskFiles as small path tables.
Every change marks the project dirty; save regenerates `project_config.js`.

## Acceptance

- Wizard → project on disk → (with Spec 04) it builds and runs unmodified; the
  generated `build.sh` also works from a plain terminal on Linux.
- Round-trip: change target to ROM_ASCII8 + romSize 128 in UI → generated file
  diff shows exactly those lines.
- Import of `<msxgl>/projects/template/` yields correct machine/target values
  (unit-test the sandbox evaluator against that real folder).
- `customConfig: true` project: IDE never touches `project_config.js` (watchdog
  test: mtime unchanged after settings save + build).
